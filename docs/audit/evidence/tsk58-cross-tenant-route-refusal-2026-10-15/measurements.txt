## 4. Why the earlier draft of the test file was wrong (recorded because it is the instructive part)

Its first run showed 403s on the two adoption cases and looked like a pass. The
403 was `CSRF_CHECK_FAILED` (`src/api/router.ts:1188-1196`): cookie-authenticated
JSON writes need the CSRF cookie + header pair, and the test had sent only the
session cookie. With the pair sent, the same requests returned **201** — i.e.
before the fix the route really did hand tenant A's record to tenant B. A second
"pass" came from the route ignoring `body.assetId` entirely
(`src/api/router.ts:8103-8114` never reads it), so the assetId vector is not an
HTTP vector today; that case is now a domain-level assertion and says so, and
the HTTP assertions use the reachable key vector instead.

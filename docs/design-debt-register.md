## 2. Debt Elimination Protocol

1. **No Silent Accumulation:** Every new visual shortcut or mock must be recorded here with an owner and concrete expiry date.
2. **Review Cadence:** During each release gate review (BG0–BG9), the Engineering Lead and Brand Owner review active debt items. Expired items block subsequent release gate clearance.
3. **Audit Trail:** When a debt item is resolved, update its status to `RESOLVED`, note the resolving commit hash, and archive it in the quarterly audit log.

## 3. DEBT-009 closure — the census is zero, and the ceiling is gone

**Closed 2026-11-19.** The ceiling this section used to rank (251 sites, by reach) no longer exists: the
sweep in `tests/unit/html-escape-census.test.ts` asserts an empty list, and the recorded constant was
deleted rather than set to zero, so there is nothing left to ratchet.

### What the rule says now

An interpolation into markup is unescaped when **neither** of these is true:

- it is wrapped in an escaping call — `${escapeHtml(value)}`;
- its value is **proved escaped at its definition** — assigned from `escapeHtml(...)`/`esc(...)`/
  `sanitize*`/`encodeURIComponent`, from a builder whose every interpolation is escaped, from a
  conditional whose every branch proves, or from a `??`/`||` whose every operand proves.

The rule is applied **per interpolation**, not per line. The previous line-level test exempted a whole
line that mentioned `escapeHtml(`, so `${content}` sitting beside `${escapeHtml(classes)}` was never
counted; 54 of the remaining sites were of exactly that shape and are now escaped.

### The escape-once rule, and why 17 variables are recorded instead of wrapped

Escaping twice is not safer, it is wrong: `escapeHtml(escapeHtml("O'Brien"))` prints `O&amp;#039;Brien`
to the reader. So the sweep accepts a value that is already escaped, and the burn-down wrapped only what
was not. Seventeen variables hold escaped **markup** rather than text — a fragment assembled over several
statements, or by a helper that escapes its own leaves — and cannot be proved from one assignment.
They are listed in `ESCAPED_FRAGMENTS` with the reason and a proof pattern that must still match the
file, so an entry cannot outlive its justification:

| File | Variables |
|---|---|
| `src/web/components/index.ts` | `ariaDisabled`, `ariaBusy`, `ariaLabel`, `actionAttr`, `ariaInvalid`, `disabledAttr`, `requiredAttr`, `pulseDot`, `iconHtml`, `sourceHtml`, `disclaimer`, `content` |
| `src/web/ia/gated-parts.ts` | `trail` |
| `src/web/workspace/governance-and-operations.ts` | `fourEyesTag` |
| `src/web/workspace/media-picker.ts` | `selector`, `stateBadge`, `notes` |

Everything else that reaches markup is either wrapped at the interpolation or proved at its definition.

### The write boundary: `html`, so the escape is not a call to remember

Zero sites still rested on one thing: an author remembering `escapeHtml(...)`. The 1,012 hand-written
calls in `src/web` were correct because a scanner checked them afterwards, not because an unescaped
interpolation was impossible to write. `src/web/components/escape.ts` now also exports a tagged template —

```ts
const rows = tasks.map((t) => html`<tr><td>${t.title}</td></tr>`);
return html`<table><tbody>${rows}</tbody></table>`;
```

— where the tag escapes every `${…}` that is not itself `SafeHtml`, arrays are interpolated element by
 element (so a row list composes without a `join` that would turn markup back into text, which the next
interpolation would then escape), and `0`/`null` behave as `escapeHtml` already made them. `SafeHtml` is
branded with a compile-time symbol *and* a `Symbol.for` runtime key, so markup from a second copy of the
module is still recognised as markup instead of escaped twice.

The three workspace surfaces are migrated as the worked example — `src/web/workspace/work-hub.ts`
(`UX-HUB-001` My Work, `UX-HUB-002` Authorised Search, `UX-HUB-003` Notifications) — and
`renderMasterLayout` (`src/web/public/dashboard.ts`) now accepts `string | SafeHtml`, so a migrated
renderer composes into the shell without an escaping call at the join. The migration is deliberately one
module at a time: it demonstrates the shape and the instruments that read it, rather than rewriting 1,012
correct sites.

The nine `src/web/ia/journey-*.ts` gated renderers are the second family, migrated on 2026-11-19 because
their shared `section(id, title, body)` wrapper interpolated a plain `string` body into markup and both
instruments rightly read that as an unescaped parameter. `section` now takes `SafeHtml` and composes with
the tag; each call site passes an `html` body, so its `${…}` are escaped at the write boundary instead of
by a remembered call (the now-redundant `escapeHtml(...)` wrappers inside those bodies were removed, not
kept — escaping twice prints `&lt;td&gt;`). The builders a body interpolates (`sourceNotConnected`,
`pendingTable`, `hostedStatesSection` in `src/web/ia/gated-parts.ts`, and the local `taskTable`,
`entryPoints`, `sessionFacts`, inbox and session-table builders) return `SafeHtml` for the same reason: a
pre-escaped fragment composed into a tagged template must be markup, not text. The four
`journey-*::body` and `journey-circ::tenant` claims that the census had recorded as escaped fragments are
deleted with the fix — they excused the raw interpolation, which no longer exists.

Both instruments read the tag as the boundary. `tests/helpers/escaped-markup.ts` treats an interpolation
inside an `html` template as escaped and records `HTML_TEMPLATE = /^(?<![.\w$])html\s*`/` so the
identifier is followed, not the spelling (`templates.html\`…\`` is still judged), and a `SafeHtml` local
interpolated into a plain template is markup; `tests/helpers/plain-string-params.ts` applies the same
rule on the taint side, so a request-derived value inside an `html` template is not a finding while the
same value in a plain template still is.

### What holds it

- `tests/unit/html-escape-census.test.ts` — zero unescaped interpolations; the fragment claims and their
  proofs; the escape helper's behaviour (including `escapeHtml(0) === "0"`); and a self-test that feeds
  the rule files which must produce exactly one finding, so the sweep cannot pass by being broken.
- `tests/unit/html-escape-taint.test.ts` — the derivation-based instrument: no value traced from the
  request, database or environment reaches markup unescaped, including across export/import edges and
  through domain-typed parameters.
- `tests/unit/html-write-boundary.test.ts` — the primitive's own contract: escaping without an
  escaping call, `SafeHtml` composed into a page without a second escape (asserting the absence of
  `&lt;td&gt;`), the array row list, `0`/`null`, a hostile `toString`, and the cross-module brand.
- `tests/unit/reflected-input-escape.test.ts` and `tests/integration/reflected-input-escape.test.ts` —
  the behavioural cases, held independently of either scanner. The unit suite's `workspace work
  surfaces (write boundary)` block hands a hostile `WorkTask`, search record and notification to the
  three migrated renderers and to the master layout, and asserts both halves — no raw payload *and* the
  escaped form present — so a renderer that silently dropped the record would still fail.

### The limit that remains

`escapeHtml` escapes text, attribute and URL contexts, and the helper is proven to neutralise the
break-out characters. Neither instrument proves the absence of XSS: they prove that no interpolation
reaches markup without escaping, under rules a reviewer can attack. A value assembled as markup by a
builder that escapes each leaf is exactly what the seventeen recorded fragments are, and a *new* such
builder is a finding until it is recorded with its proof.
